<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cancellation/stop signals→background goroutines | Concurrent shutdown signals must not leak workers or leave blocked waits behind. |
| background sync passes→legacy FTP connections | Runner shutdown must release network-side resources created by the legacy sync engine. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-03-01 | D | shutdown path | mitigate | Use one idempotent shutdown path with `sync.Once`, timer stop, watcher close, goroutine wait, and `done` closure exactly once. |
| T-07-03-02 | D | retry sleeps and worker waits | mitigate | Use context-aware cancellation for retry-wrapped operations and require tests that `Stop`/cancel unblock `Wait()`. |
| T-07-03-03 | R | final lifecycle status | mitigate | Store latest runtime error separately from final wait result so embedders can inspect both current health and terminal completion. |
</threat_model>
